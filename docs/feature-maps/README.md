## Automation and environments

| Automation status | Meaning |
| --- | --- |
| Script present; execution TBD | A matching local JavaScript specification exists. No pass result or approved-requirement coverage is implied. |
| TBD — no verified script mapping | A source case exists; an exact correspondence to a repository script has not been verified. |
| TBD — case inventory unavailable | Module scope is known but standalone authoritative case records are unavailable. |

Each module has a separate traceability table with **Test Case ID**, **Playwright JavaScript script**, **DEV result**, **STG result**, and **Run date / evidence**. For future execution, append dated rows or link an immutable run record. Record Passed, Failed, Skipped, Blocked, or Not run only when supported by the relevant run. Retain prior results and record the target URL, release/build, commit, browser, data profile, and report/trace link with each run.

| Environment | Purpose | Configuration and current evidence |
| --- | --- | --- |
| DEV | Development Environment | Set `MAIPS_BASE_URL` to the verified DEV endpoint for the selected application. Confluence lists public, internal, and external DEV hosts; current routing and credentials require verification. Results: TBD. |
| STG | Staging Environment | The existing configuration defaults to `https://digital-stg.maips.gov.my/` when `MAIPS_BASE_URL` is absent. Confluence also identifies the internal `/internal` route. Results: TBD. |

[playwright.config.js](../../playwright.config.js) currently has a single browser project named `chromium`, using Microsoft Edge, and reads one `MAIPS_BASE_URL` for each invocation. It does not define DEV/STG projects. Select an environment through the process environment and use separate credentials and run artifacts. No automation scripts or configuration were changed for these maps.

Example PowerShell run layout, **for future authorized execution only**; replace the URL and run identifier with verified values:

~~~powershell
# DEV example; select a test scope appropriate to the chosen application.
$env:MAIPS_BASE_URL = '<verified-DEV-base-URL>/'
$env:PLAYWRIGHT_JSON_OUTPUT_FILE = 'test-results/DEV/run-identifier/results.json'
npx playwright test tests/zakat --output='test-results/DEV/run-identifier/artifacts' --reporter=line,json

# STG example, in a separate invocation with STG credentials.
$env:MAIPS_BASE_URL = 'https://digital-stg.maips.gov.my/'
$env:PLAYWRIGHT_JSON_OUTPUT_FILE = 'test-results/STG/run-identifier/results.json'
npx playwright test tests/zakat --output='test-results/STG/run-identifier/artifacts' --reporter=line,json
~~~

Use unique run identifiers for every execution. The examples select Zakat specifications; choose Authentication or a particular case path when appropriate. Existing authentication scripts contain hard-coded screenshot paths under `test-results`; those paths do not follow `--output`. Preserve them with the matching environment/run before another run can replace them. The default HTML report folder is shared as well. Keep executions isolated and archive their artifacts without altering the existing scripts as part of documentation work.

## Maintenance and deduplication

1. Locate the authoritative source record before adding a case. Preserve its release, scenario ID, case ID, description and ordered steps. Use `TBD` for unavailable fields, including scenario totals; never manufacture identifiers or business rules.
2. Keep one lowercase, hyphenated Markdown filename per owning module. Retain the eight-column feature table in the requested order and the separate environment execution table. Add module links and recalculate available-case counts in this index.
3. Deduplicate first by the authoritative internal test ID, then by Jira key or local case ID. Repeated text alone is insufficient to merge different roles, releases, channels or preconditions. If IDs collide with conflicting content, retain the conflict for verification.
4. `TC-MAIP-ELIG-SYS-04` appears with identical titles and descriptions in [MAIP-999](https://qa-milradius.atlassian.net/browse/MAIP-999) and [MAIP-1001](https://qa-milradius.atlassian.net/browse/MAIP-1001). It occupies one row in the Individu map, preserving both Jira keys. Xray step equivalence remains `TBD`. All other distinct source identities remain separate.
5. Do not duplicate an approved case when implementing it in Playwright. Add the verified JavaScript link to its existing row, preserve the original case ID in the test title or annotations, and use the traceability table for DEV/STG execution. If a local case is confirmed to implement a Jira case, reconcile them into one canonical row while preserving both IDs and all original content in traceability notes.
6. Append new releases to the owning module. Retain historical cases; mark superseded or retired status explicitly once verified. Keep environment data and results independent; never copy a pass from DEV to STG.
7. When a master document or the reference example becomes available, reconcile it against these source identities, fill the missing metadata and steps, verify module assignments, and record the source revision and date. Check every added script link and index count before committing.
